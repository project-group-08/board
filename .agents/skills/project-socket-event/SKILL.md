# Событие Socket.IO

## 1. Контракт

- Имя события в виде `область:действие`, например `comment:changed`. Схема payload лежит в `packages/contracts/src/ws/`, событие добавляется в `ClientToServerEvents` или `ServerToClientEvents`. Правку контракта делай по скиллу `project-contracts-change`.
- Выбери вид события:
  - курсоры и положение элемента во время жеста: volatile (`socket.volatile.emit`), раз в 30-50 мс; потерять одно положение не страшно;
  - вход, выход, «редактирует», изменения данных: обычное надёжное событие; нужен ответ клиенту: подтверждение (ack).
- Событие несёт сигнал или маленький payload. Большие данные (результат ИИ, версия доски) клиент забирает запросом REST.

## 2. Бэк (apps/api)

- В обработчике каждого события: проверка payload схемой из contracts и проверка прав на доску. Ошибку проверки отдаём как `WsException`.
- Рассылка в комнату доски. Изменения документа сначала сохраняем, потом рассылаем. Где бэк их хранит, ещё не решено (раздел «Ещё не решено» корневого AGENTS.md): хранилище сам не выбирай, спроси.
- Наблюдателю запрещены события, которые несут изменения документа.

## 3. Фронт (apps/web)

- Сокет один на вкладку. Событие обрабатывает владелец данных: TanStack Query (`setQueryData` или `invalidateQueries`), стор присутствия или движок через интерфейс синхронизации.
- Подписку снимай при размонтировании и при уходе с доски.
- Данные события не копируй в `useState` и Zustand.

## 4. Проверь

- Тест на фейковом транспорте: событие доходит; неверный payload и событие без прав отклоняются; повторная доставка не создаёт дублей.
- Volatile-события не вызывают ни одной перерисовки React (проверка в React Profiler): их рисует слой курсоров движка.

Справка: https://socket.io/docs/v4/emit-cheatsheet/ и https://socket.io/docs/v4/rooms/; разделы 6 и 8 в `docs/architecture/frontend.md`.
