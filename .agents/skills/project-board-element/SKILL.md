# Новый элемент доски или инструмент

## 1. Схема (packages/contracts/src/board)

- Схема элемента: `type: z.literal('<тип>')`, общие поля (`id`, `index`, `parentId`), геометрия по смыслу типа и свои поля. У стикера и фигуры `x`, `y`, `w`, `h`; у стрелки id элементов и точки крепления, геометрию считаем при отрисовке.
- Добавь схему в `ElementSchema` (`z.discriminatedUnion('type', ...)`). Правка по скиллу `project-contracts-change`.
- Старый фронт новый тип не знает: напиши в PR, что увидит открытая вкладка со старым кодом.
- Сервер проверяет элементы документа той же `ElementSchema`. Бэк с новой схемой выкатываем раньше фронта, иначе старый сервер отклонит апдейт с новым типом, а клиент сбросит свой документ. Порядок выкатки напиши в PR.

## 2. Документ (packages/board-doc)

- Чтение и запись полей нового типа в `Y.Map` элемента. Старые документы без новых полей читаются без ошибок.

## 3. Движок (packages/board-engine)

- Реестр элементов: геометрия, отрисовка, экспорт.
- Отрисовка только в `src/render` через Konva; остальной движок о Konva не знает.
- Элемент с картинкой: загрузка с `crossOrigin = 'anonymous'`, иначе экспорт в PNG упадёт.
- Инструмент: новое состояние в машине состояний инструментов. Элемент создаётся одной транзакцией с origin `LOCAL`.
- Пространственный индекс обновляется при создании, перемещении и удалении.
- Стрелки, привязанные к элементу, переживают его удаление: конец становится свободной точкой.

## 4. Интерфейс (apps/web)

- Кнопка инструмента и панель свойств лежат там же, где редактор доски (`_pages/board`), пока они нужны одной странице.
- Текущий инструмент и выделение берутся из движка через `useSyncExternalStore`.

## 5. Тесты

- Движок без DOM: создание, перемещение, отмена, копирование с перепривязкой стрелок, удаление элемента со стрелкой.
- Два клиента в памяти: одновременная правка нового элемента.
- Рендер и экспорт в PNG: браузерный режим Vitest.
