# packages/contracts: общие схемы и типы

Единственный источник типов, которыми обмениваются `apps/web`, `apps/api` и `apps/worker`. Zod 4. Общие правила в корневом [AGENTS.md](../../AGENTS.md).

## Устройство

- `common/`: id, роли (owner, editor, viewer), матрица прав, лимиты, коды ошибок, пагинация.
- `http/`: DTO запросов и ответов по ресурсам (auth, workspaces, members, boards, comments, versions, invites, files, ai).
- `ws/`: имена событий, схемы payload, `ClientToServerEvents` и `ServerToClientEvents`, версия протокола.
- `board/`: элементы доски (стикер, фигура, текст, изображение, стрелка, группа), стили и геометрия.
- `ai/`: плоские схемы ответов модели и операции превью.

## Правила

- Тип выводим из схемы, руками не дублируем:

```ts
export const ElementSchema = z.discriminatedUnion('type', [
  StickySchema, ShapeSchema, TextSchema, ImageSchema, ConnectorSchema, GroupSchema,
])
export type BoardElement = z.infer<typeof ElementSchema>
```

- Интерфейс вместо схемы допустим только для контракта поведения, например карты событий сокета.
- Схемы ложатся на JSON: даты через `z.iso.datetime()` (не `z.string().datetime()` и не `z.date()`), без `transform`. Иначе ломаются `z.toJSONSchema` и схемы для ИИ.
- Схемы ответов ИИ плоские и отдельные от схем приложения.
- Меняем только добавлением: новое поле необязательное или со значением по умолчанию. Удаление, переименование и смена типа только через ADR и новую версию протокола: в браузерах ещё открыты вкладки со старым фронтом.
- Пакет не импортирует другие пакеты репозитория и не содержит логики приложений: только схемы, типы и константы. Внутри пакета импорты относительные: пакет собирает tsc.
- Лимиты (размер файла, число элементов, запросы к ИИ) держим константами здесь; числа ставим по замерам прототипа и согласуем с бэком.
- Перед любой правкой схем открой скилл `project-contracts-change`.
