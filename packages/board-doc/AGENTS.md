# packages/board-doc: документ доски на Yjs

Чтение и запись Y.Doc без DOM и без Konva. Пакет нужен и фронту, и серверу: сервер проверяет апдейты, восстанавливает версии и двигает пины комментариев. Общие правила в корневом [AGENTS.md](../../AGENTS.md).

Синхронизация на Yjs поверх Socket.IO ([ADR-0005](../../docs/adr/0005-yjs-sync.md)); подробно в разделе 8 [архитектуры](../../docs/architecture/frontend.md).

## Правила

- Yjs 13.6.x. В репозитории одна копия `yjs`: не смешивай импорт ESM и CommonJS и не ставь вторую версию, иначе ломаются проверки instanceof.
- Элемент доски хранится как `Y.Map` по id и сливается по полям. Текст элемента хранится строкой: пока его редактирует один участник, у других редактор закрыт.
- Изменения только транзакцией с origin: свои с `LOCAL`, чужие с origin провайдера. По origin отмена отличает свои правки от чужих.
- Присутствие (курсоры, выделение, «кто редактирует») и камера в документ не попадают.
- Ссылка на удалённый элемент допустима: CRDT не запрещает одновременно удалить элемент и привязать к нему стрелку. Код, который читает документ, это терпит.
- Изменение устройства документа (новое поле элемента, новый тип) должно читать старые документы. Новый тип элемента добавляй по скиллу `project-board-element`; ломающее изменение только через ADR.
- Внутри пакета импорты относительные, без алиасов путей: пакет собирает tsc.
- Тесты: Vitest без DOM. Сценарии двух клиентов в памяти: одновременные правки, повторная доставка апдейта, обрыв связи, удаление при правке.
