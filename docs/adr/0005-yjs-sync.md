# ADR-0005: Синхронизация доски на Yjs поверх Socket.IO

- Статус: Принято
- Дата: 11.11.2026
- Кто решил: архитектор фронтенда
- Связано: [архитектура, раздел 8](../architecture/frontend.md), [ADR-0006](0006-konva-canvas.md)

## Контекст

ТЗ требует совместную правку в реальном времени, в том числе когда участники подключены к разным инстансам бэка, и не разрешает слать всю доску после каждого изменения. Повторная доставка события не должна создавать дубли или применять изменение второй раз. Отмена действий и история версий в ТЗ разные функции. Транспорт реального времени уже Socket.IO.

## Решение

Документ доски хранится в Y.Doc (Yjs 13.6.x; ветку 14 не берём, пока она RC). По сети идут только апдейты Yjs поверх Socket.IO через свой небольшой провайдер на y-protocols: вход на доску, обмен state vector в обе стороны, апдейты. Присутствие (курсоры, выделение) идёт отдельными событиями и в документ не попадает. Где бэк хранит документ, решаем отдельно (список «Ждут решения команды» в [README](README.md)).

## Рассмотренные варианты

- Свой протокол операций с сервером-арбитром (как в Figma): дедупликацию по opId, порядок операций, досылку после обрыва и отмену пишем сами; для нескольких инстансов нужен один счётчик операций на доску.
- Готовые серверы Hocuspocus и yhub: работают на своём WebSocket, рядом с Socket.IO появился бы второй канал со своей авторизацией. y-socket.io заброшен с 2023 года.

## Последствия

- Одновременные правки сливаются сами. Апдейт можно применить повторно и в любом порядке, поэтому дублей нет без доработок.
- После обрыва стороны досылают друг другу только недостающее по state vector.
- Y.UndoManager отменяет только свои транзакции (origin `LOCAL`).
- Апдейты сходятся в любом порядке: инстансам бэка не нужен общий счётчик операций.
- Провайдер поверх Socket.IO пишем сами.
- Апдейт двоичный: бэк проверяет права, схему и лимиты после применения к копии документа.
- Документ растёт: нужны склейка апдейтов в снимок и сборка мусора Yjs. Если версии будут снимками Yjs, им нужен `gc: false`; как храним версии и где бэк хранит документ, ещё решаем.
- В репозитории одна копия `yjs`, иначе ломаются проверки instanceof.
