# ADR-0004: Фронт и API на одном домене через Caddy

- Статус: Принято
- Дата: 11.11.2026
- Кто решил: архитектор фронтенда
- Связано: [архитектура, раздел 4](../architecture/frontend.md), инфраструктура (обратный прокси Caddy)

## Контекст

Фронт (Next.js) и API (NestJS: REST и Socket.IO) работают отдельными процессами. Сессия живёт в httpOnly cookie. Если API на другом домене или порту, браузеру нужен CORS с credentials, а cookie на другой сайт уходит только с SameSite=None. В инфраструктуре уже выбран обратный прокси Caddy.

## Решение

Сайт и API на одном домене. Caddy отправляет `/api` и `/socket.io` в Nest, остальные пути в Next. WebSocket Caddy проксирует сам. Браузер обращается к API и сокету по относительным путям.

## Рассмотренные варианты

- API на своём поддомене или порту: CORS с credentials, cookie с SameSite=None и лишние настройки на обеих сторонах.
- Прокси через rewrites в Next: каждый запрос к API шёл бы через процесс Next, а Caddy в инфраструктуре уже есть.

## Последствия

- CORS не нужен, cookie сессии уходят сами.
- Локально сайт тоже открываем через Caddy: на порту Next запросы к `/api` попадут в Next, а не в Nest.
- Пути `/api` и `/socket.io` забирает Caddy: Route Handlers Next под ними работать не будут.

## Что меняется для агентов

В `apps/web/AGENTS.md` и `apps/api/AGENTS.md` добавлены правила про один домен; вопрос убран из «Ещё не решено» в корневом AGENTS.md.
