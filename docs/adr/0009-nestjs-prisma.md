# ADR-0009: Бэкенд на NestJS 12 и Prisma 7

- Статус: Принято
- Дата: 12.11.2026
- Кто решил: архитектор фронтенда; ответственный за бэкенд может пересмотреть решение новым ADR до первой задачи по бэкенду
- Связано: [ADR-0003](0003-zod-validation-on-backend.md), [apps/api/AGENTS.md](../../apps/api/AGENTS.md)

## Контекст

ТЗ задаёт NestJS и одну из ORM: Prisma или TypeORM. ADR-0003 оставлял версию NestJS на выбор бэкенда. Чтобы каркас ставил зависимости бэкенда вместе с фронтендом, версии нужно зафиксировать.

## Решение

- NestJS 12 (12.5 на 12.11.2026): запросы проверяются схемами Zod из `packages/contracts` встроенным `StandardSchemaValidationPipe`, документация Swagger строится из тех же схем. Nest CLI 12 работает на TypeScript 6.0, который закреплён в репозитории.
- Prisma 7 (7.10 на 12.11.2026): схема базы и миграции в `apps/api/prisma`, типизированный клиент генерируется из схемы.
- Каркас ставит пакеты NestJS (ядро, Express, Socket.IO, Swagger, конфиг, BullMQ, тестирование, CLI), BullMQ 6, Prisma и клиент Prisma. Код и схему базы пишет бэкенд.

## Рассмотренные варианты

- NestJS 11: прошлая ветка, для схем Zod понадобился бы пакет `nestjs-zod`.
- TypeORM 1.x: модели на классах с декораторами и более слабая типизация; Prisma ближе к подходу «типы из схемы», который используется в `contracts`.

## Последствия

- У CLI Prisma метка `latest` в npm указывает на 8.0 RC, поэтому мажорная версия в catalog задана явно; `prisma` и `@prisma/client` держим одной версии.
- Prisma при установке скачивает движок: она разрешена в `allowBuilds`.
- Для запуска бэкенда и миграций нужны Postgres и Redis, локально из Docker Compose. Установка и сборка работают без них.

## Что меняется для агентов

`apps/api/AGENTS.md`: версия NestJS и ORM записаны, проверка запросов через `StandardSchemaValidationPipe`, миграции только Prisma. Скилл `project-setup` ставит зависимости бэкенда.
