# Архитектурные решения (ADR)

Здесь записываем решения по архитектуре: что решили, почему и какие варианты отвергли. AGENTS.md говорит агентам, что делать, а ADR объясняет почему. Если правило в AGENTS.md спорит с ADR, правим одно из них в PR.

## Как вести

- Файл `NNNN-<коротко-латиницей>.md` по шаблону [0000-template.md](0000-template.md), номера по порядку.
- Статусы: «Предложено» (ждёт решения команды), «Принято», «Отклонено», «Заменено ADR-NNNN».
- Принятый ADR не переписываем. Решение поменялось: пишем новый ADR, у старого ставим «Заменено».
- Решение меняет правило для агентов: в том же PR правим AGENTS.md. ADR пиши сам или попроси агента открыть скилл `project-adr`.

## Ждут решения команды

Открытые вопросы по архитектуре. На доске их больше нет, поэтому вопрос и рекомендацию ведём здесь. По каждому после решения пишем ADR и убираем строку отсюда и из «Ещё не решено» в корневом AGENTS.md:

- Где хранится состояние доски на бэке. Рекомендация: журнал апдейтов в Postgres, периодически склеиваем в снимок; рассылка через redis-streams-adapter.
- Лимиты: размер файла, число элементов на доске, запросы к ИИ. Рекомендация: константы в `packages/contracts`, числа по замерам прототипа, согласуем с бэком.
- Как храним версии. Рекомендация: на каждую версию полная копия состояния; живой документ остаётся со сборкой мусора Yjs.
- Cache Components в Next 16.4. Рекомендация: убрать флаги cacheComponents и partialPrefetching в первой версии, приложение в основном клиентское.
- React Compiler. Рекомендация: на старте не включать, он плохо уживается с изменяемыми объектами (Y.Doc, узлы холста) и watch() из React Hook Form.
- Какие письма шлёт бэк: подтверждение почты, сброс пароля, приглашение по почте? Рекомендация: подтверждение почты и сброс пароля по одноразовой ссылке, остальные уведомления через Telegram, как в ТЗ.
- Что значит «базовое форматирование» текста. Рекомендация: стиль всего блока (жирный, курсив, размер, цвет, выравнивание), текст хранится строкой.
- Права наблюдателя: может ли комментировать, видят ли его курсор? Рекомендация: комментировать не может, курсор видят все.
- Восстановление версии при участниках. Рекомендация: всем приходит обычная правка и уведомление «Иван восстановил версию от 12:30», стеки отмены сбрасываются.
- Кто раскладывает черновик ИИ: модель отдаёт координаты блоков или раскладку считает воркер? Рекомендация: модель отдаёт блоки и связи, раскладку делает воркер (например, dagre или elkjs).
- Загрузка файлов в S3: через бэк или по подписанной ссылке. Решаем с бэком, рекомендации нет.
